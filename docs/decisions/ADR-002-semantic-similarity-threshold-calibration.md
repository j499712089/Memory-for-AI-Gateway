# ADR-002: 语义相似度阈值校准机制

## Status
Accepted (2026-08-22)

## Context

ALL-158 的完成判据将语义有效性断言阈值固化为「同义文本对余弦 > 0.5、无关文本对 < 0.3」。测试侧实测证明该阈值对中文不可满足，原因如下：

1. **模型词表覆盖问题**：当前 `all-MiniLM-L6-v2` 模型的 30,522 词表中仅含 488 个 CJK 条目，85% 的中文字符落入 `[UNK]` token
2. **向量空间塌缩**：大量 `[UNK]` token 导致中文句向量被同一批 `[UNK]`/`[CLS]`/`[SEP]` 主导，向量整体向零点同侧塌缩
3. **阈值击穿**：实测中文无关文本对余弦相似度为 0.41-0.47，全部超过 0.3 阈值，导致正确实现被误判为不合格

实测数据对比：

| 语言 | 同义对余弦 | 无关对余弦 | 阈值满足情况 |
|------|-----------|-----------|-------------|
| 英文 | 0.81-0.93 | 0.00-0.05 | ✓ 满足 > 0.5 / < 0.3 |
| 中文 | 0.56-0.99 | 0.41-0.47 | ✗ 无关对全部 > 0.3 |

若不校准阈值，即使 ALL-154 用真实 ONNX 模型完全正确实现，也会在 ALL-155 验收时失败，产生第四轮返工。

## Decision

采用**语言分档校准 + 相对分离度兜底**的双层断言机制：

### 1. 语言分档绝对阈值

按语言分别校准阈值，存储为配置文件：

```yaml
# test/semantic/thresholds.yml
thresholds:
  en:
    synonym_min: 0.5      # 同义文本对最低余弦相似度
    unrelated_max: 0.3    # 无关文本对最高余弦相似度
  zh:
    synonym_min: 0.55     # 待 ALL-159 模型选定后重测校准
    unrelated_max: 0.45   # 待 ALL-159 模型选定后重测校准
```

- **英文阈值**：沿用 `> 0.5` / `< 0.3`（已验证有效）
- **中文阈值**：依赖 ALL-159 模型选型结果，用同一校准脚本重测得出
- **禁止跨语言复用**：不同模型在不同语言上的向量分布差异巨大

### 2. 相对分离度兜底断言

添加不依赖绝对阈值的相对断言：

```
同一语言内：min(同义对余弦) - max(无关对余弦) > 0.15
```

- **跨模型稳定**：相对分离度不受模型向量空间整体偏移影响
- **防止模型退化**：确保同义/无关向量在空间中可区分
- **兜底保护**：防止「换模型即全体误判」

### 3. 校准脚本架构

在 `test/semantic/` 下建立校准子系统：

```
test/semantic/
├── calibrate.go          # 校准脚本主入口
├── thresholds.yml        # 校准结果配置
├── probe_data.go         # 探针文本对（英文/中文）
└── semantic_test.go      # ALL-155 验收用例（引用 thresholds.yml）
```

**关键设计约束**：

- **复用编码逻辑**：调用 `internal/embedding.Service.Encode()`，不得复制第三份编码实现（见 ALL-158 N4）
- **UTF-8 强制**：脚本必须强制 UTF-8 读写，避免 Windows PowerShell 中文 mojibake
- **失败诊断**：断言失败时打印实际余弦值与 `[UNK]` 计数，区分阈值问题与分词问题
- **幂等可重复**：支持模型切换后重新校准

### 4. 集成路径

- **ALL-158 契约修订**：删除写死的 `> 0.5` / `< 0.3`，改为 `引用 test/semantic/thresholds.yml`
- **ALL-155 验收用例**：从 `thresholds.yml` 读取阈值，同时检查相对分离度
- **模型版本绑定**：在 `thresholds.yml` 中记录校准时的模型路径与文件哈希，防止模型漂移

## Consequences

### 正面后果

1. **防止误判**：避免正确实现因阈值不当被验收拒绝
2. **模型适配性**：支持多语言模型选型，不锁死单一模型
3. **可维护性**：阈值配置化，模型切换后可快速重新校准
4. **自动化验收**：相对分离度断言提供跨模型稳定的兜底检查

### 负面后果

1. **初始工时**：需实现校准脚本（约 200-300 行 Go 代码）
2. **依赖 ALL-159**：中文阈值终值依赖模型选型决策，模型未定前无法完成校准
3. **维护成本**：模型升级时需重新校准（但已自动化，成本可控）

### 风险缓解

- **阻断关系明确**：本任务 blocks ALL-158（契约）和 ALL-155（用例），串行依赖清晰
- **探针文本固化**：校准脚本内置探针文本对，避免人工选取导致的偏差
- **双层断言**：绝对阈值 + 相对分离度，任一失败均拦截

## Implementation Notes

1. **优先级排序**：
   - P0: 实现校准脚本框架（与模型无关）
   - P0: 添加相对分离度断言（与模型无关）
   - P1: 等待 ALL-159 模型选型决策
   - P1: 执行中文阈值校准并更新配置

2. **验收条件**：
   - 校准脚本可执行且输出符合 `thresholds.yml` 格式
   - 英文探针通过绝对阈值 + 相对分离度双重检查
   - 中文探针在模型选定后通过校准
   - ALL-155 验收用例可从 `thresholds.yml` 读取阈值并断言

3. **回退路径**：
   - 若 ALL-159 决定保留 `all-MiniLM-L6-v2`（仅支持英文），则在契约中显式声明放弃中文检索，ALL-155 验收项同步删除中文用例
